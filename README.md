# Cup

Private iPhone bra-fit measurement app for Alissa, backed by the private Google Sheet named **Cup**.

## Privacy architecture

- `index.html` runs the camera and MediaPipe measurement workflow in the browser.
- Raw capture images remain in browser memory and are cleared when the page is reloaded/closed.
- Raw images are not posted to Google Apps Script or stored in Google Sheets.
- `backend/Code.gs` accepts measurement data only and rejects image/base64/blob payloads.
- `functions/_middleware.js` provides a **server-side password gate** when deployed on Cloudflare Pages.
- The website password is **not** stored in this repository. Store it as the Cloudflare Pages secret/environment variable `CUP_PASSWORD`.

## Repository layout

- `index.html` — iPhone camera + on-device automatic analysis
- `manifest.webmanifest` — installable web-app metadata
- `sw.js` — web-app/service-worker shell
- `functions/_middleware.js` — Cloudflare server-side password protection
- `backend/Code.gs` — Google Sheet backend for the existing Cup spreadsheet

## 1. Google Sheet backend

The backend is already pointed at the existing Cup spreadsheet.

1. Open the Cup Google Sheet.
2. Extensions → Apps Script.
3. Replace `Code.gs` with the contents of `backend/Code.gs` from this repository.
4. Run `setupCup()` once and authorize it.
5. Copy the API key shown in the execution log.
6. Deploy → New deployment → Web app.
   - Execute as: **Me**
   - Who has access: **Anyone**
7. Copy the `/exec` deployment URL.

The Apps Script endpoint cannot save measurements without the long API key. To revoke the old API key, run `rotateCupApiKey()`.

## 2. Deploy the protected camera site with Cloudflare Pages

Do **not** enable public GitHub Pages for this project. Use Cloudflare Pages because this repository contains a server-side authentication middleware.

1. In Cloudflare, create a **Pages** project and connect GitHub repository `drbellschool/cup`.
2. Framework preset: **None**.
3. Build command: leave blank.
4. Build output directory: `/` (repository root).
5. Add an encrypted Pages environment variable/secret named `CUP_PASSWORD` and give it a strong password known only to Adam and Alissa.
6. Deploy.

When the site opens, the browser will ask for credentials. The username can be anything; the password must match `CUP_PASSWORD`. Authentication is enforced by Cloudflare before `index.html` is served.

## 3. Connect the iPhone app to the Sheet

On Alissa's iPhone:

1. Open the protected Cloudflare Pages URL in Safari.
2. Enter the site password.
3. In Cup, paste the Apps Script `/exec` URL.
4. Paste the API key generated by `setupCup()`.
5. Tap **Save on this iPhone**.
6. Safari → Share → Add to Home Screen if desired.

## Security notes

No web system can guarantee zero possibility of a data leak. This design reduces exposure substantially by keeping the repository private, enforcing server-side password access, keeping the Google Sheet private, storing the Sheet API key separately in Apps Script Script Properties, and never intentionally uploading raw camera images.

The site currently downloads MediaPipe runtime/model files from Google/jsDelivr. The measurements run in the browser, but those third-party hosts will still receive ordinary network metadata such as IP address and user agent when the model assets are fetched. If maximum isolation is required, vendor the MediaPipe assets into the private deployment instead of using a CDN.
